One NestJS app, two ways to run it.

The same AppModule runs as a long-lived server on your machine and as one Vercel function in production. Only the hosts around it change.

Every request passes the same checks, in the same order.

Middleware and global guards run for all 11 endpoints. Access is denied by default, and each stage that can reject a request returns its own error code in one standard error format.

  1. Express middleware

    1. request-idKeeps a UUID X-Request-Id or creates one, then echoes it backnever rejects
    2. pino loggerLogs request ID, user and response time when the request completesnever rejects
    3. helmetCSP default-src 'none', HSTS, nosniff, Cache-Control: no-storenever rejects
    4. CORSAllows only origins listed in CORS_ORIGINS, without credentialsbrowser blocks
    5. content-typePOST and PATCH must send application/json415 UNSUPPORTED_MEDIA_TYPE
    6. JSON parser16 kb limit; keeps the raw body for signature checks413 PAYLOAD_TOO_LARGE

  2. Global guards

    1. IpRateLimitGuardFixed 60-second window per IP, per route group429 RATE_LIMITED
    2. AuthGuardVerifies the JWT and the device signature. Only @BearerOnly() and @HealthProbe() routes skip the signature401 (8 codes)
    3. UserRateLimitGuardSame window, counted per signed-in user429 RATE_LIMITED
    4. RolesGuardChecks @Roles('ADMIN') on admin routes403 FORBIDDEN

  3. Handler

    1. TimeoutInterceptorStops waiting after REQUEST_TIMEOUT_MS (10 s)504 REQUEST_TIMEOUT
    2. ZodValidationPipe.strict() schemas reject unknown fields; free text is stripped of HTML400 VALIDATION_FAILED
    3. controller → use caseBuilds the Actor, then a domain policy decides who may act on what402 · 403 · 404 · 409
    4. GlobalExceptionFilterMaps each DomainError code to its status and the { error: { code, message, requestId } } bodyformats every error

A stolen token is not enough.

Each login session binds one ECDSA P-256 public key. After that, every request must be signed with the matching private key, sent within 60 seconds, and never replayed.

String the client signs (ECDSA P-256, SHA-256, IEEE-P1363)

base64url(sha256(accessToken))

Bound to the session

The key is tied to Supabase's session_id, so a token from another login cannot use it.

Covers the whole request

Method, URL, body hash and token hash are signed, so changing any of them breaks the signature.

Known gap

A token stolen in the first 5 minutes, before the client binds its key, could be bound by someone else. The real client then sees KEY_ALREADY_BOUND.

The domain doesn't import Nest, Prisma or Redis.

Each module has the same layers. Controllers call use cases, use cases depend only on interfaces, and ESLint's no-restricted-imports blocks framework imports inside domain/.

Quota is spent only after the answer exists.

The AI call happens outside the transaction. Quota is deducted afterwards, inside a single transaction with row locks, so there is no pending state and nothing to refund.

3 free messages a month

One row per user and UTC month ('YYYY-MM'). A new month means a new row, so no reset job is needed.

Bundles per billing cycle

Basic 10, Pro 100, Enterprise unlimited. Each renewal resets used_messages.

Fixed lock order

Bundles are always locked in ID order, so two requests from the same user can't deadlock.

Every subscription that ends records why.

A subscription is ACTIVE or INACTIVE, and an inactive one keeps a reason. Payments are simulated with a configurable failure rate.

Five tables in PostgreSQL.

User IDs come from Supabase, so the API never stores credentials. Everything else belongs to a user.
